# Step 1 — Deep QA Audit (UX/UI) · GACP Lite

วิธีตรวจ: บูตระบบจริง (web 3100 / api 8100 / Postgres) แล้วถ่ายหน้าจอ 26 ภาพ
ที่ desktop 1440×900 และ mobile 390×844 · light + dark · ทั้งก่อนและหลังแก้
ภาพอยู่ที่ `shots/` (ก่อน) และ `after/` (หลัง) · ทุกข้อสรุปวัดจากเบราว์เซอร์จริง ไม่ใช่จากการอ่านโค้ด

## 1. Executive Summary

โครงสร้างการมองเห็นของ Lite แข็งแรงกว่าที่คาด เพราะสืบทอดระบบสีและ typography ที่ผ่านการ
ปรับมาแล้วจากระบบเต็ม — ระยะห่าง ลำดับความสำคัญ และสัดส่วนการ์ดใช้ได้ทันที

แต่ **ความเสียหายไม่ได้อยู่ที่ pixel มันอยู่ที่ "หน้าที่ไม่มีอะไรอยู่"** ตอนตัดระบบเป็น Lite
หน้าจอถูกลบไปหลายหน้า และสิ่งที่ชี้ไปหาหน้าเหล่านั้นไม่ได้ถูกตามไปแก้ · ผลคือผู้ใช้จริง
สามในสี่ตำแหน่งเจอทางตันตั้งแต่วินาทีแรกหลังล็อกอิน

ถ้า Steve Jobs เปิดดูรุ่นก่อนแก้ เขาจะไม่ได้พูดถึง grid — เขาจะถามว่าทำไมล็อกอินเข้ามาแล้ว
หน้าจอว่างเปล่า และทำไมเครื่องที่ตั้งโหมดมืดยังได้จอสว่าง

**คะแนนก่อนแก้: ไม่ผ่าน** (4 ข้อวิกฤต) · **หลังแก้: ผ่าน** (เหลือ polish 5 ข้อ)

## 3. Actionable Improvements

### 🔴 Critical Compromise — แก้แล้วทั้งหมด

**C-01 · ธีมเพิกเฉยต่อค่าที่เครื่องผู้ใช้ตั้งไว้**
วัดจริง: `prefersDark=true` แต่ `body bg = rgb(244,246,245)` (สว่าง) และสคริปต์เขียน
`localStorage.theme='light'` ทับลงไป ทำให้ติดค้างถาวรแม้แก้บั๊กแล้ว
สาเหตุ: `theme-script.tsx` ตอบ `'light'` ตายตัว ไม่เคยเรียก `matchMedia`
แก้: ถาม `prefers-color-scheme` เมื่อผู้ใช้ยังไม่เคยเลือกเอง และ **ไม่เขียน localStorage**
เพราะค่าที่ระบบเดาให้ไม่ใช่การตัดสินใจของผู้ใช้
หลังแก้: `prefersDark=true` → `html.class="dark"`, `body bg = rgb(12,18,15)`

**C-02 · ฝ่ายบัญชีล็อกอินแล้วเจอหน้าว่าง**
วัดจริง: `getNavForRole('account')` คืน 0 รายการ (ตำแหน่งอื่นได้ 1-9)
สาเหตุ: `ACCOUNT_NAV` เป็นอาร์เรย์ว่าง — ผมสร้างหน้าและให้สิทธิ์ แต่ไม่ได้ใส่เมนู
แก้: เพิ่มรายการ `fee-queue → /provider/accounting`

**C-03 · หน้าฝ่ายบัญชีอยู่นอกโครงหน้าจอเจ้าหน้าที่**
โครง (`ProviderLayout`) ไม่ได้อยู่ใน `app/provider/layout.tsx` — ทุกหน้า import เอง
ผมลืม ผลคือไม่มีแถบนำทาง ไม่มีทางกลับ และเนื้อหาชนขอบจอที่ x=0
แก้: ครอบด้วย `<ProviderLayout>`

**C-04 · แถบแดงค้างบนหัวทุกหน้าของผู้ยื่น**
`entity-switcher` เรียก `/api/entities/*` ที่ Lite ตัดทิ้ง ขึ้น "โหลดพื้นที่ทำงานไม่สำเร็จ"
ตลอดเวลา ทั้งที่งานของผู้ใช้สำเร็จดี — คำเตือนที่เตือนเรื่องที่ไม่มีอยู่ ทำให้คำเตือนจริงถูกมองข้าม
แก้: ถอดออก (Lite มีหน่วยงานเดียว ผู้ยื่นมีตัวตนเดียว ไม่มีอะไรให้สลับ)

### 🟡 Polish Opportunity

**P-01 · หน้าเลือกทางเข้าลอยครึ่งบน** — เนื้อหาจบที่ 470px บนจอ 900px
แก้แล้ว: `flex min-h-screen flex-col justify-center` (มือถือถอยไปเกาะบนเองเมื่อเนื้อหายาวกว่าจอ)

**P-02 · ป้ายคอลัมน์งวดขึ้น "ไม่ทราบสถานะ"** — ส่งข้อความไทยเข้าช่อง `status` แทน `label`
แก้แล้ว: แยก `status` (รหัสเลือกโทนสี) กับ `label` (ข้อความที่คนอ่าน)

**P-03 · แถบสรุป 3 ตัวเลขกระจายบนความกว้าง 1400px** — ช่องว่างระหว่างตัวเลขมากเกินจน
สายตาไม่จับกลุ่ม · ยังไม่แก้ — ควรจำกัดความกว้างหรือใช้ grid ที่แน่นกว่านี้

**P-04 · คอลัมน์ในตารางกว้างไม่สมดุล** — "งวด" ได้พื้นที่มากเกิน ส่วนตัวเลขเบียดขวา
ยังไม่แก้

**P-05 · localStorage ยังเก็บ `theme=light` แม้หน้าจะเป็นดาร์ก** — ตัวสคริปต์ไม่อ่านค่านั้นแล้ว
จึงไม่กระทบการแสดงผล แต่ถ้ามีโค้ดอื่นอ่านตรง ๆ จะได้คำตอบที่ขัดกับสิ่งที่ตาเห็น
ยังไม่แก้ — ต้องไล่ว่า ThemeProvider เขียนมันตอนไหน

## 4. สิ่งที่ตรวจแล้วไม่พบปัญหา

- **ไม่มีการเลื่อนแนวนอนบนมือถือ** — วัด `scrollWidth/clientWidth` ทั้ง 6 หน้า ได้ 390/390 ทุกหน้า
  (ภาพ fullPage กว้างกว่า viewport เป็นสิ่งปกติของการถ่ายภาพ ไม่ใช่การล้น — ตรวจซ้ำแล้ว)
- ปุ่มและลิงก์มี focus ring ที่มองเห็นได้
- ข้อความไทยไม่ถูกตัดกลางคำ line-height รองรับวรรณยุกต์
