## 🟠 HIGH · PII-01 · "ไม่ใช่บุคคลทั่วไป" ไม่ได้แปลว่า "เป็นเจ้าหน้าที่"

**ตำแหน่ง:** `apps/backend/routes/api/fees/fee-payments.js:158`

```js
const isOfficer = Boolean(req.user?.providerId)
               || normalizeRole(req.user?.role) !== 'health';
```

`normalizeRole` คืน `null` กับทุกคำที่ไม่อยู่ใน `ROLE_ALIASES`
(`canonical-rbac.js:204`) เงื่อนไขจึงอ่านว่า `null !== 'health'` = จริง =
**เป็นเจ้าหน้าที่** · ค่าเริ่มต้นของการตัดสินสิทธิ์กลายเป็น "ผ่าน" ซึ่งกลับด้าน

**วัดจริงก่อนแก้** — สร้างบุคคลทั่วไปคนที่สองบน scratch DB (คนละเจ้าของกับใบที่ทดสอบ)
โทเคนของผู้ใช้คนเดียวกัน ต่างกันแค่ค่า `role`:

```
role: 'health'         ->  404 ไม่พบคำขอนี้            (ถูกต้อง)
role: 'farmer_legacy'  ->  200 {applicationNumber, phase1Amount, phase2Amount,
                                feePayments[].confirmedBy{firstName,lastName}}
```

บทบาทที่ระบบไม่รู้จักเกิดได้จริง: โทเคนที่ออกก่อนการรวบบทบาทใน Step 2.1 หรือแถวผู้ใช้
ที่ค่า `role` ไม่ได้อยู่ในรายการแล้ว

คอมเมนต์ใน `routes/api/system/tickets.js:25` บันทึกว่าโค้ดชุดนี้เคยเจอบั๊กชนิดเดียวกัน
มาแล้ว — *"`'HEALTH' !== 'health'` is true … made the old gate dead code"*

**แก้แล้ว** — `isProviderRole(req.user?.role)` ซึ่งล้มแบบปิด (คำที่ไม่รู้จักคืน `false`)

**หลังแก้:**
```
บุคคลทั่วไปคนที่สอง role: 'health'        -> 404
บุคคลทั่วไปคนที่สอง role: 'farmer_legacy' -> 404
เจ้าของใบ                                 -> 200
เจ้าหน้าที่ admin / scheduler / account    -> 200 ทั้งสามคน
```
เฝ้าโดย `__tests__/unit/who-is-an-officer-is-decided-by-a-list-not-by-a-negation.test.js`

## 🟠 HIGH · PII-02 · สิทธิ์ขอสำเนาข้อมูลของตนเองใช้ไม่ได้

**ตำแหน่ง:** `services/pdpa-service.js:182` → `GET /api/auth/health/me/export`

```
HTTP 500
log: TypeError: Cannot read properties of undefined (reading 'findMany')
     at assembleUserDataExport (services/pdpa-service.js:182)
```

`prisma.invoice` เป็น `undefined` — โมเดล `Invoice` ถูกตัดออกตอนแยก Lite (ลูกค้าเก็บ
เงินด้วยช่องทางของตัวเอง เจ้าหน้าที่บันทึกเป็นแถว `FeePayment`) แต่บริการ PDPA ยัง
ถามหามัน

นี่คือสิทธิ์ตาม **PDPA ม.30** (ขอเข้าถึงและขอรับสำเนาข้อมูลของตน) เจ้าของข้อมูลกดแล้ว
ได้ 500 ทุกครั้ง และไม่มีอะไรบอกใครว่ามันพัง

**แก้แล้ว** — สำเนาข้อมูลรวมแถว `FeePayment` ที่ผูกกับคำขอของเขา แทนใบแจ้งหนี้ที่
ระบบนี้ไม่ได้ออก

**หลังแก้:** `HTTP 200 · 11,963 ไบต์` — applications 2 · feePayments 1 ·
notifications 2 · ไม่มีแฮชรหัสผ่านในผลลัพธ์ · `subject.retainUntil` มาครบ

## 🟠 HIGH · PII-03 · โค้ดที่ยังถามหาโมเดลที่ถูกลบไปแล้ว

ตอนแยก Lite โมเดลหลายตัวถูกตัดออก แต่โค้ดที่เรียกใช้ไม่ได้ถูกตามไปแก้ทุกที่ ·
เดินกราฟ `require` จาก `server.js` (รวมทาง `createLazyRouter`) แล้วเทียบกับ
`PrismaClient` จริง — **14 จุดในไฟล์ที่เข้าถึงได้**

| แก้แล้ว | เดิม | ตอนนี้ |
|---|---|---|
| `pdpa-service.js` | `prisma.invoice.findMany` | `feePayment` — PII-02 |
| `admin-dashboard-service.js` | `prisma.invoice.aggregate` | `feePayment.aggregate` |
| `report-controller.js` | `prisma.invoice.findMany` | `feePayment.findMany` |
| `document-service.js` ×5 | `prisma.sOPDocument.*` | ลบทั้งชุด — SOP อยู่ในรายการ PURGE ไม่มีผู้เรียก |
| `routes/api/admin/plants.js` | `prisma.plantingCycle.findFirst` | ตรวจกับ `Application.plantId` ผ่าน `config/plant-species-slugs.js` |

`admin-dashboard-service.js` น่าสนใจเป็นพิเศษ — คอมเมนต์เหนือฟังก์ชันเขียนไว้เองว่า
*"ไม่มีโมเดล Payment — prisma.payment เป็น undefined แล้วถูก catch เปล่า ๆ ของผู้เรียก
กลืน แดชบอร์ดผู้ดูแลจึงรายงานรายรับเป็น 0 ตลอดกาล"* แล้วแก้ด้วยการไปใช้ `Invoice`
ซึ่งตอนนี้ก็ถูกตัดออกไปแล้วเหมือนกัน — **อาการเดิมกลับมาอีกชั้นหนึ่ง**

**เฝ้าโดย** `__tests__/unit/no-code-may-ask-for-a-model-that-was-deleted.test.js`
ซึ่งเดินกราฟเองทุกครั้ง · เทสรุ่นแรกของผมนับข้อความในคอมเมนต์เป็นการเรียกจริง
(`// Replaces inline prisma.invoice.findMany`) จึงฟ้องสองไฟล์ที่แก้ไปแล้ว — เทสที่
ฟ้องผิดเชื่อไม่ได้พอ ๆ กับเทสที่ฟ้องไม่ได้ ตอนนี้ลอกคอมเมนต์ก่อนตรวจ

## 🟠 HIGH · REF-07 · บันทึกการมอบหมายงานไม่เคยถูกเขียนเลย — **รอคำตัดสิน**

4 จุดที่เหลือคือ `prisma.assignmentLedgerEntry` · โมเดลถูกตัดออกตอนแยก Lite แต่
ฟีเจอร์ยังถูกเรียกจาก **ห้าที่ที่ใช้งานอยู่จริง**: มอบหมายผู้ตรวจเอกสาร ·
เปลี่ยนผู้ตรวจเอกสาร · เปลี่ยนผู้ตรวจแปลง · มอบหมายเป็นชุดจากหน้าผู้ดูแล ·
และ API อ่าน `/api/provider/ledger`

การเขียนถูก **กลืน error** ไว้ (`assignment-ledger-service.js`:
*"Never break the assignment on a ledger failure"*) ผลจึงไม่ใช่ 500 แต่คือ
**ทุกการมอบหมายไม่ถูกบันทึกเลยตั้งแต่วันแรกของ Lite** และหน้าอ่าน ledger ว่างเปล่าตลอด

> หมายเหตุ: ฟีเจอร์เปลี่ยนผู้ตรวจที่ผม mount กลับใน Step 3.1 (REF-02) ก็เขียน ledger
> ไม่ได้เหมือนกัน · การเปลี่ยนผู้ตรวจ **ทำงาน** แต่ไม่มีร่องรอยว่าใครเปลี่ยนให้ใคร

**สองทางเลือก ต้องให้ operator ตัดสิน** — ผมไม่เลือกให้ เพราะทั้งสองทางเปลี่ยน
ความหมายของข้อมูล ไม่ใช่แค่ย้ายโค้ด:

1. **เอาโมเดลกลับเข้าสคีมา** — ตรงไปตรงมา ของเดิมทำงานทันที · เป็น migration
2. **ย้ายไปเขียนที่ `AuditLog`** ซึ่งอยู่ในรายการ RETAIN ของสเปก Lite อยู่แล้ว —
   ไม่เพิ่มตาราง แต่ต้องเขียน query service ใหม่ทั้งตัว (`count` / `findMany` /
   `groupBy` คนละรูป) และ `/api/provider/ledger` จะตอบช้าลงเพราะต้องกรองจาก
   audit log ทั้งกอง

ระหว่างรอ เส้นฐานในเทสตรึงไว้ว่ามีเท่านี้ **ลดได้อย่างเดียว** — ของใหม่เพิ่มไม่ได้
และของที่จ่ายแล้วต้องถูกลบออกจากรายการ ไม่งั้นเทสฟ้องเช่นกัน

## ✅ ตรวจแล้วแข็งแรง — ไม่ต้องแก้

**ประตูยืนยันรับเงิน** `POST /api/fees/:applicationId/:phase/confirm`
- จำนวนเงินมาจาก `Application.phase1Amount` / `phase2Amount` ของแถวนั้น
  **ไม่ใช่จาก request body** — ผู้เรียกแก้ตัวเลขไม่ได้
- สิทธิ์มาจาก `canRoleTransition` ที่เดียว ไม่ทำสำเนากติกามาไว้ในไฟล์
- ตรวจสถานะต้นทางก่อน (`FEE_NOT_DUE` ถ้ายังไม่ถึงงวด)
- `@@unique([applicationId, phase])` — สองแท็บกดพร้อมกันก็เดินสถานะครั้งเดียว
  และแถวเงินเกิดก่อนการเดินสถานะ ลำดับนี้ทำให้ไม่มีทางเดินซ้ำ
- บันทึกว่า **ใครยืนยัน เมื่อไร อ้างอิงอะไร**

**`/api/admin/users`** — คืน 7 แถว ไม่มีเลข 13 หลักเต็ม ไม่มีเบอร์โทร ไม่มีแฮชรหัสผ่าน
`identityNumber` และ `healthId` ถูกปิดบางส่วนทุกแถว

## หมายเหตุเรื่องวิธี

การทดสอบ PII-01 รอบแรกของผมไม่สมเหตุสมผล: ผมมินต์โทเคนโดยใช้ `id` ของเจ้าของใบจริง
แล้วเปลี่ยนแค่ค่า `healthId` ในโทเคน — auth middleware อ่านผู้ใช้จากฐานข้อมูลด้วย `id`
แล้วเขียน `healthId` ทับ ผลที่ได้จึงเป็น "เจ้าของอ่านใบตัวเอง" ไม่ใช่การทดสอบ IDOR ·
ต้องสร้างบุคคลทั่วไปคนที่สองจริง ๆ ถึงจะวัดได้ (สร้างบน scratch DB และลบแล้ว)
