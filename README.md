# GACP Lite

ระบบยื่นขอและออกใบรับรอง GACP — ตัดจากระบบเต็มให้เหลือเส้นทางเดียว
พร้อม deploy และรันได้เองโดยไม่ต้องพึ่งบริการภายนอกใด ๆ

```
ยื่นคำขอ → ชำระค่าตรวจเอกสาร → เจ้าหน้าที่ตรวจเอกสาร
        → ชำระค่าตรวจแปลง → ตรวจแปลง → ออกใบรับรอง
```

## เริ่มใช้งาน

```bash
cp .env.example .env          # แล้วเติมค่าให้ครบ — สามค่าแรกไม่มีค่าเริ่มต้น
docker compose up -d --build
docker compose exec api npx prisma migrate deploy --schema prisma/schema
docker compose exec api node prisma/seed-lite.js
```

เปิด http://localhost:3100 · API อยู่ที่ http://localhost:8100

### บัญชีเจ้าหน้าที่

seed สร้างให้เฉพาะ **ผู้ดูแลระบบคนแรก** — ตั้ง `ADMIN_IDENTIFIER` (เลขบัตร 13 หลัก)
กับ `ADMIN_INITIAL_PASSWORD` ใน `.env` แล้วรัน seed อีกครั้ง

เจ้าหน้าที่ที่เหลือเป็นคนจริงของหน่วยงาน จึงไม่ถูก seed · ผู้ดูแลสร้างเองที่หน้า
จัดการผู้ใช้ หรือผ่าน API:

```bash
curl -X POST http://localhost:8100/api/admin/users/provider \
  -H "Authorization: Bearer <โทเคนผู้ดูแล>" -H 'Content-Type: application/json' \
  -d '{"providerId":"<เลขบัตร 13 หลัก>","email":"...","password":"...",
       "firstName":"...","lastName":"...","role":"account"}'
```

`role` ใช้ค่าใดค่าหนึ่งใน `account` · `scheduler` · `document_reviewer` · `auditor` · `admin`

> **ผู้ดูแลระบบเดินคำขอไม่ได้เลย โดยตั้งใจ** — ไม่มีขั้นตอนไหนในเส้นทางที่ `admin`
> กดได้ นั่นคือการแบ่งแยกหน้าที่ ไม่ใช่ข้อบกพร่อง · ถ้ายังไม่ได้สร้างเจ้าหน้าที่
> คำขอจะค้างอยู่ที่ขั้นแรกตลอดไป

## ตำแหน่งงานในระบบ

| ตำแหน่ง | ทำอะไรได้ | ขยับคำขอจาก → ไป |
|---|---|---|
| ผู้ขอรับรอง (`health`) | ยื่นคำขอ แนบเอกสาร ดูสถานะและค่าธรรมเนียม ดาวน์โหลดใบรับรอง | ร่าง → ยื่น · ส่งฉบับแก้ไขกลับเข้าคิว |
| บัญชี (`account`) | ยืนยันว่ารับค่าธรรมเนียมแล้ว ทั้งสองงวด | รอชำระ → ชำระแล้ว |
| คนจัดคิว (`scheduler`) | มอบหมายผู้ตรวจเอกสาร · นัดวันตรวจแปลง | ชำระแล้ว → เข้าคิวตรวจ / ยืนยันนัดตรวจ |
| ผู้ตรวจเอกสาร (`document_reviewer`) | ตรวจเอกสารคำขอ · ส่งกลับให้แก้ไข | เข้าคิวตรวจ → ผ่าน / ส่งกลับแก้ |
| ผู้ตรวจแปลง (`auditor`) | บันทึกผลตรวจแปลง · ออกข้อบกพร่อง · ออกใบรับรอง | ยืนยันนัด → ผ่าน / CAR / ไม่ผ่าน → ออกใบรับรอง |
| ผู้ดูแลระบบ (`admin`) | สร้างบัญชีเจ้าหน้าที่ · ตั้งค่าระบบ | — ไม่อยู่ในเส้นทางเดินคำขอโดยตั้งใจ |

ห้าตำแหน่งแรกถือคนละท่อนของเส้นทาง และเดินของคนอื่นไม่ได้ — คนที่บอกว่าเงินเข้าแล้ว
ไม่ใช่คนเดียวกับคนที่ตรวจเอกสาร และคนจัดคิวไม่ใช่คนตัดสินผล

กติกาอยู่ที่เดียวคือ `ROLE_TRANSITIONS` ใน `services/workflow-transition-service.js`
ทุกประตูถามที่นั่น ไม่มีประตูไหนทำสำเนากติกาไว้เอง

## ค่าธรรมเนียม

ระบบนี้ **ไม่รับชำระเงิน** · หน่วยงานเก็บเงินด้วยช่องทางของตัวเอง แล้วเจ้าหน้าที่
บันทึกในระบบว่ารับแล้ว — คำขอจึงเดินต่อ

แต่ละงวดยืนยันได้ครั้งเดียว และแถวที่บันทึกไว้ระบุเสมอว่าใครเป็นผู้ยืนยัน เมื่อไร
จำนวนเท่าไร และอ้างอิงเอกสารใด (`FeePayment`)

ราคาอยู่ที่ `apps/backend/config/business-rules.js` และแก้ทับได้ผ่านตาราง
`SystemConfig` โดยไม่ต้องแก้โค้ด

## สิ่งที่ระบบนี้ไม่มี (และไม่ควรถูกคาดหวังว่ามี)

- ระบบสอบกลับสินค้า (Track & Trace) และ QR ของล็อต
- บันทึกการปลูก การเก็บเกี่ยว การอบแห้ง
- ฐานความรู้สมุนไพร · แบบสำรวจ · เครื่องมือสร้าง SOP
- การเชื่อมต่อ IdP ของรัฐ (ThaiD / หมอพร้อม) — ล็อกอินด้วยรหัสผ่าน + JWT ภายใน
- ระบบบัญชีและเอกสารการเงิน (ใบเสนอราคา ใบแจ้งหนี้ ใบเสร็จ ใบลดหนี้)
- ระบบหลายหน่วยงาน — ตาราง `Organization` มีแถวเดียวตรึงไว้ ดูเหตุผลใน
  `apps/backend/prisma/schema/tenancy.prisma`
